# 前端单元测试设计方案（v2）

## 1. 核心理念：发现 → 生成 → 执行

与 E2E 页面测试和 API 接口测试保持一致的三阶段模式。

### 1.3 文件存储结构

采用**轻量配置 + 外部重数据**分离存储：

```
┌─ server/data/                    ← 轻量配置（随项目 Git 管理，KB 级）
│  └── projects/{id}/
│     ├── project.json               E2E 页面集数据（已有）
│     ├── discovery-result.json      E2E 发现结果（已有）
│     ├── page-context.json          E2E 页面知识库（已有）
│     ├── frontend-discovery.json    前端组件/函数发现结果（新增）
│     └── frontend-tests/            生成的 vitest 测试文件（新增）
│         ├── utils/
│         ├── components/
│         └── stores/
│
└─ {testDataDir}/                  ← 统一外部数据目录（设置页面配置一项即可）
   ├── e2e/                          E2E 运行数据（原 e2eDataDir 迁入）
   ├── api/runs/
   ├── frontend/
   │   └── runs/{suiteId}.json         前端测试运行记录
   └── codereview/runs/
```

> **设计原因**：所有测试类型的运行产物统一放一个外部目录，
> `server/data/` 只保留轻量 JSON 配置。
> 设置页面只需配一个 `testDataDir`（如 `F:/test-runs-data`）。

## 3. 发现阶段：Claude Code 扫描源码

### 3.1 触发入口

在设置页面项目管理中，新增 **「发现组件」** 按钮（与"发现页面""发现接口"并列）。

### 3.2 API 端点

```
POST /api/projects/{id}/discover-frontend
  触发 Claude Code 扫描源码中的 Vue 组件/工具函数/Store
  SSE 流式返回发现进度

GET /api/projects/{id}/frontend-discovery
  获取已保存的前端发现结果
```

### 3.3 发现 Prompt

```
你是一个前端代码分析专家。请分析以下项目的前端源码，找出所有可测试的单元。

## 项目信息
- 项目名称: {{projectName}}
- 源码路径: {{sourcePath}}
- 前端框架: Vue 3 + Vite + Pinia

## 任务
1. 扫描 src/ 目录下的 .vue/.ts/.js 文件
2. 按 4 个类别分组：
   - utils: 纯工具函数（无 DOM 依赖，最易测试）
   - components: Vue 组件中的计算属性、事件处理逻辑
   - stores: Pinia/Vuex Store 的 actions/getters
   - pages: 页面级交互逻辑
3. 对每个文件记录：导出函数/组件、可测试逻辑、复杂度

## 注意
- 优先选择有明确输入输出的函数（最容易写单元测试）
- 跳过纯 UI 展示组件（无逻辑，不适合单元测试）
- 标注复杂度：low（纯函数）/ medium（有状态）/ high（有副作用）

## 输出格式
请输出 JSON 格式（frontend-discovery.json 的 modules 结构）...
```

### 3.4 发现进度 SSE

  message: string
  detail?: {
    currentFile?: string

    foundStores?: number
  }
}

## 4. 生成阶段：Claude Code 生成测试文件

### 4.1 生成策略

Claude Code 基于发现结果，为每个可测试文件生成对应的 `.test.ts` 文件：

| 发现类别 | 测试风格 | 示例 |
|---------|---------|------|
| **utils** | 直接 import 源函数，测试输入输出 | `mergeCurrentMessage([], msg) → [msg]` |
| **components** | 提取计算逻辑/事件处理，纯逻辑断言 | `canSend = text.trim() !== '' && !isLoading` |
| **stores** | 模拟 Store 操作，测试状态变更 | `createChat('新') → activeChatId 更新` |
| **pages** | 模拟多组件交互流程 | `switchChat(id) → input 清空` |

### 4.2 生成 Prompt

```
你是一个前端测试专家。请根据以下发现结果，为每个文件生成 vitest 单元测试。

## 已发现的可测试文件
{{frontend-discovery.json 的内容}}

## 测试风格要求
1. 使用 vitest 的 describe/it/expect
2. 所有描述使用中文
3. 按功能模块分组（describe），按场景细分（子 describe）
4. 对于 utils：直接 import 源函数，给定输入断言输出
5. 对于 components：提取计算逻辑为纯函数测试（不 mount 组件）
6. 使用 beforeEach 重置状态

## 参考：之前的测试风格
{{mergeCurrentMessage.test.js 的部分内容作为参考}}

## 输出
为每个文件生成完整的 .test.ts 文件内容...
```

### 4.3 生成的测试文件存放

```

│   └── merge-message.test.ts
├── components/

## 5. 执行阶段

### 5.1 执行策略

由于测试文件引用了源码项目的函数（`import` 源码路径），执行时需要：

```typescript
async function runFrontendTest(suite: TestSuite, config: Record<string, unknown>): Promise<void> {
  const projectId = config.projectId as string
  const project = getProjectById(projectId)
  const sourcePath = project?.sourcePath
  if (!sourcePath) throw new Error('项目未配置源码路径')

  const testsDir = path.join(DATA_DIR, 'projects', projectId, 'frontend-tests')
  if (!fs.existsSync(testsDir)) {
    throw new Error('请先在设置页面「发现组件」')
  }

  // 生成临时 vitest 配置，将源码路径映射为 alias
  const vitestConfig = generateVitestConfig(testsDir, sourcePath)

  for (const tc of suite.cases) {
    tc.status = 'running'
    saveRun(suite)
    testBus.emit('test:update', { suiteId: suite.id, caseId: tc.id, caseName: tc.name, status: 'running' })

    const testFile = path.join(testsDir, tc.metadata.file)
    const startTime = Date.now()

    try {
      // 执行单个测试文件
      const result = execSync(
        `npx vitest run "${testFile}" --config "${vitestConfig}" --reporter=json 2>&1`,
        { cwd: AI_PLATFORM_ROOT, timeout: 60000, encoding: 'utf-8' }
      )
      tc.duration = Date.now() - startTime
      parseVitestResult(tc, result)
    } catch (err: any) {
      tc.duration = Date.now() - startTime
      tc.status = 'error'
      tc.error = err.stderr?.slice(0, 500) || err.message
    }

    saveRun(suite)
    testBus.emit('test:update', { suiteId: suite.id, caseId: tc.id, caseName: tc.name, status: tc.status })
  }
}
```

### 5.2 vitest 临时配置

```typescript
function generateVitestConfig(testsDir: string, sourcePath: string): string {
  // 在 ai-platform 的 web/ 目录下创建临时 vitest 配置
  // 关键：将 @/ alias 指向源码项目的 src/
  const configContent = `
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    globals: true,
    environment: 'happy-dom',
    include: ['${testsDir.replace(/\\/g, '/')}/**/*.test.ts'],
  },
  resolve: {
    alias: {
      '@': '${sourcePath.replace(/\\/g, '/')}/src',
    },
  },
})
`
  const configPath = path.join(testsDir, '_vitest.config.ts')
  fs.writeFileSync(configPath, configContent)
  return configPath
}
```

## 8. 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 测试文件存放 | `server/data/projects/{id}/frontend-tests/` | 不污染源码项目，分项目管理 |
| 测试生成方式 | Claude Code 读取源码后生成 | AI 能理解业务逻辑，生成有意义的测试 |
| 测试执行方式 | vitest run（非 Claude Code） | 单元测试执行快，不需要 AI 介入 |
| 源码引用 | 通过 vitest config alias 映射 `@/` | 测试文件 import 源码路径，运行时解析到实际位置 |
| 组件测试风格 | 提取逻辑为纯函数测试（非 mount） | 参考 `mobile-chat-ui.test.js` 的模式，无需安装 `@vue/test-utils` |
