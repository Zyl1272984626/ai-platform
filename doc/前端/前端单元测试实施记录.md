## 一、整体流程

前端单元测试走 **发现 → 生成 → 执行** 三阶段，与 E2E 页面测试、代码审查共享同一套测试框架（Claude Code SDK + SSE 流式推送 + 中断恢复）。

```
用户操作流程：

设置页面                     测试中心
┌─────────┐                ┌──────────────────────┐
│ 发现组件  │ ──生成──→     │ 选择项目 + 勾选模块    │
│          │  discovery    │        ↓              │
│          │               │ 开始测试              │
│          │               │   ↓                   │
│  知识图谱  │ ──辅助──→     │ 阶段一：生成 .test.ts  │ ← Claude Code
│ (可选参考) │               │   ↓                   │
│          │               │ 阶段二：执行 vitest    │ ← execSync
└─────────┘                └──────────────────────┘
```

### 阶段 0：发现组件（前置条件）

- **入口**：设置页面 → 项目卡片 → 「发现组件」按钮
- **实现**：`server/src/services/frontend-discovery.ts`
- **Skill**：`skills/base/frontend-discovery/SKILL.md`
- **Claude Code** 扫描源码中的 `.vue` / `.ts` / `.js` 文件
- **输出**：`server/data/projects/{id}/frontend-discovery.json`
- **分类**：utils（纯函数）、components（组件逻辑）、stores（Pinia Store）、pages（页面逻辑）

### 阶段 1：生成测试文件

- **入口**：测试中心 → 前端单元测试 Tab → 选项目+勾选模块 → 开始测试
- **实现**：`server/src/services/test-runner.ts` → `runFrontendTest()` → `runSingleModuleFrontendTest()`
- **Skill**：`skills/tests/frontend-test/SKILL.md`
- **Claude Code** 逐模块读取源码，生成 `.test.ts` 文件
- **输出**：`server/data/projects/{id}/frontend-tests/{category}/xxx.test.ts`
- **特性**：SSE 流式进度、AbortController 中断支持、resumeInfo 中断恢复

### 阶段 2：执行 vitest

- **实现**：`server/src/services/test-runner.ts` → `executeVitestTests()`
- **动态生成** `_vitest.config.ts`（happy-dom + `@/` alias）
- **执行**：`npx vitest run --reporter=json`
- **超时**：5 分钟
- **结果**：解析 JSON 报告，统计 total/passed/failed

## 四、测试用例生成策略

按发现结果的 4 个类别采用不同策略：

| 类别 | 策略 | 示例 |
|------|------|------|
| **utils** | 直接 import 源函数，给定输入断言输出，每函数至少 3 个用例 | `formatDate(Date.now()) → '2026-06-03'` |
| **components** | 提取计算属性/事件处理为纯函数测试，不 mount 组件 | `canSubmit = text.trim() !== '' && !loading` |
| **stores** | createPinia() + 测试 action 的状态变更和 getter 计算 | `createChat('新') → activeChatId 更新` |
| **pages** | 提取页面交互逻辑为纯函数，不依赖路由和 DOM | `filterByKeyword(list, 'xxx') → filteredList` |

## 五、知识图谱的辅助价值

`page-context.json`（66 个页面的知识图谱）可以在生成阶段作为**辅助参考上下文**注入到 Skill 中：

### 可利用的数据

| 知识图谱字段 | 辅助价值 |
|-------------|---------|
| `apiEndpoints` | 为 store 测试提供 API 接口结构，辅助构造 mock 数据 |
| `interactions` | 映射为 components/pages 的测试场景（action → expected） |
| `commonIssues` | 自动生成边界/异常测试用例 |
| `description` | 为测试描述提供业务语义，让 it() 更有意义 |

### 已实现的注入机制

在 `test-runner.ts` 的 `runFrontendTest()` 中，读取 `frontend-discovery.json` 后同时读取 `page-context.json`，将匹配到的页面信息通过 `{{pageContextSection}}` 模板变量注入到 Skill prompt 中。

## 六、中断恢复机制

前端测试支持中断恢复，与代码审查共享同一套机制：

1. 每个模块生成完成后，记录 `sessionId` 和 `status: 'completed'` 到 `resumeInfo`
2. 中断时记录 `status: 'interrupted'` 和 `partialOutput`
3. 恢复时通过 `resume + forkSession` 复用 Claude Code 会话
4. 已完成的模块自动跳过（显示"跳过已生成"）

## 七、验证步骤

1. **设置页面**：为项目点击「发现组件」，等待 SSE 完成
2. **确认发现**：检查 `server/data/projects/{id}/frontend-discovery.json` 已生成
3. **测试中心**：切换到「前端单元测试」Tab，选择项目
4. **确认面板**：应显示发现摘要 + 模块勾选列表
5. **勾选模块** → 开始测试 → 观察 SSE 流式进度
6. **确认生成**：检查 `server/data/projects/{id}/frontend-tests/` 下有 `.test.ts`
7. **中断恢复**：运行中点停止，再次运行确认跳过已完成模块
