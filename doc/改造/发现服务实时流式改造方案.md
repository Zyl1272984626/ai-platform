# 发现服务实时流式改造方案

## 问题现状

### 问题1：进度不透明
点击「发现审查点」「发现接口」「发现组件」「生成图谱」等按钮后，只能看到关键词猜测的进度消息：
```
审查点发现进度 — scanning
- 开始代码审查点发现...
- 正在启动 Claude Code 扫描源码...
- 正在扫描源码目录结构...
```
实际 Claude Code 可能在读几十个文件、执行十几次工具调用，但用户完全看不到，只能干等。

### 问题2：发现失败无感知
审查点发现后显示「Invalid Date、0 模块、0 关键文件」，说明发现执行了但输出解析失败，用户无从得知原因。

### 问题3：生成图谱等待更久
「生成图谱」超时 15 分钟，还要启动 Playwright MCP 逐页打开浏览器、截图、分析，用户只能看到一行「正在逐页分析页面结构...」。

### 根本原因
当前 4 个发现服务（api-discovery / frontend-discovery / review-discovery / page-context-discovery）的架构完全一致：

```
用户点击 → 后端调用 Claude Code SDK query() → 收集全部文本到 fullOutput
→ 只通过关键词猜测推送 { stage, message } 进度
→ 完成后从 fullOutput 中正则提取 ```json``` 块 → 解析 JSON
```

问题：
1. **进度消息靠关键词猜测**：`detectReviewProgress()` 检查 `fullOutput.includes('扫描')`，不是真正的进度
2. **真实输出被吞掉**：Claude Code 的 tool_use、tool_result、文本全部堆在 `fullOutput` 字符串里，用户看不到
3. **解析脆弱**：依赖正则匹配 ` ```json``` ` 块，如果 Claude 输出格式稍有不同就解析失败（0 模块的原因）
4. **无错误可见性**：解析失败或 Claude 报错时，用户只看到「0 模块」，不知道发生了什么
5. **Playwright 工具调用不可见**：生成图谱时 Claude Code 会调用 browser_navigate / browser_snapshot / browser_take_screenshot 等工具，用户完全不知道当前在分析哪个页面

## 对比：E2E 测试页的实时流

E2E 测试页的架构：
```
用户点击测试 → 后端执行 Claude Code → 每条消息通过 testBus 事件总线广播
→ SSE 端点订阅事件总线 → 前端 EventSource 接收
→ 构建 blocks 数组（text / tool_use / tool_result）
→ markdown 渲染文本 + ToolCallBlock 组件渲染工具调用
```

关键优势：
- 用户实时看到 Claude Code 在读什么文件、调什么工具、输出了什么
- 工具调用有折叠面板，可以看到 Read/Grep 的结果
- 文本输出用 markdown 渲染，排版清晰

## 改造方案

### 核心思路
复用 E2E 测试页的流式架构模式，将 3 个发现服务改造为实时流式输出，不再等全部完成后才解析。

### 改造范围

#### 1. 后端：发现服务流式输出（核心改动）

**改动文件**：`server/src/services/api-discovery.ts`、`frontend-discovery.ts`、`review-discovery.ts`

**改造方式**：`onProgress` 回调从简单的 `{ stage, message }` 扩展为传递原始 Claude Code 消息块：

```typescript
// 改造前
onProgress?: (progress: { stage: string; message: string; detail?: any }) => void

// 改造后 — 增加原始消息类型
onProgress?: (progress: DiscoveryProgress) => void

type DiscoveryProgress =
  | { type: 'stage'; stage: string; message: string }                    // 阶段切换
  | { type: 'text'; content: string }                                     // Claude 文本输出
  | { type: 'tool_use'; name: string; input: any; toolUseId: string }    // 工具调用
  | { type: 'tool_result'; toolUseId: string; result: any; isError?: boolean } // 工具结果
  | { type: 'done'; discovery: any; rules?: any }                        // 完成，带结果
  | { type: 'error'; message: string }                                   // 错误
```

**服务层改造**（以 review-discovery 为例）：

```typescript
// 改造后的 for await 循环
for await (const msg of response) {
  if (abortController.signal.aborted) throw new Error('超时');

  if (msg.type === 'assistant' && (msg as any).message?.content) {
    for (const block of (msg as any).message.content) {
      if (block.type === 'text') {
        // 实时推送文本，不再堆 fullOutput
        onProgress?.({ type: 'text', content: block.text });
      } else if (block.type === 'tool_use') {
        // 推送工具调用
        onProgress?.({
          type: 'tool_use',
          name: block.name,
          input: block.input,
          toolUseId: block.id,
        });
        // 同时收集到 fullOutput 供最终解析
        fullOutput += `\n[Tool: ${block.name}] ${JSON.stringify(block.input)}\n`;
      }
    }
  }

  if (msg.type === 'tool_result') {
    const resultBlock = (msg as any).message?.content?.find(
      (b: any) => b.type === 'tool_result'
    );
    if (resultBlock) {
      onProgress?.({
        type: 'tool_result',
        toolUseId: resultBlock.tool_use_id,
        result: typeof resultBlock.content === 'string'
          ? resultBlock.content.slice(0, 2000)  // 截断防止过大
          : String(resultBlock.content).slice(0, 2000),
        isError: resultBlock.is_error,
      });
    }
  }
}
```

#### 2. 后端：路由层透传（无需大改）

`server/src/routes/projects.ts` 中的 SSE 端点无需改动结构，只需把 `sendSSE(progress)` 改为透传新的消息格式：

```typescript
// 改造前：只推 stage+message
await discoverReview(project.id, (progress) => { sendSSE(progress); });

// 改造后：透传全部消息类型，包括 tool_use/tool_result
await discoverReview(project.id, (progress) => { sendSSE(progress); });
```

无需修改，因为 `sendSSE` 本来就是 `JSON.stringify(data)` 透传。

**实现方式**：复用 TestView 的 blocks 模式，在进度面板中渲染：

```typescript
// 每个 discovery 操作维护一个 blocks 数组
const discoveryStreams = reactive<Record<string, {
  blocks: Array<{
    type: 'text' | 'tool_use'
    content?: string
    name?: string
    input?: any
    toolUseId?: string
    result?: any
    isError?: boolean
  }>
  stage: string
}>>({})

// SSE 回调中构建 blocks
function handleDiscoverySSE(projectId: string, event: any) {
  if (!discoveryStreams[projectId]) {
    discoveryStreams[projectId] = { blocks: [], stage: '' }
  }
  const stream = discoveryStreams[projectId]

  if (event.type === 'text') {
    // 追加到最后一个 text block 或创建新的
    const last = stream.blocks[stream.blocks.length - 1]
    if (last?.type === 'text') {
      last.content += event.content
    } else {
      stream.blocks.push({ type: 'text', content: event.content })
    }
  } else if (event.type === 'tool_use') {
    stream.blocks.push({
      type: 'tool_use',
      name: event.name,
      input: event.input,
      toolUseId: event.toolUseId,
    })
  } else if (event.type === 'tool_result') {
    const toolBlock = stream.blocks.find(
      b => b.type === 'tool_use' && b.toolUseId === event.toolUseId
    )
    if (toolBlock) {
      toolBlock.result = event.result
      toolBlock.isError = event.isError
    }
  } else if (event.type === 'stage') {
    stream.stage = event.message
  }
}
```

**模板**：复用 ToolCallBlock 组件渲染工具调用：


#### 4. 关于日志保存

**不保存原始流**。理由：
- Claude Code 一次发现可能产生几十KB~几百KB 的文本 + 工具调用
- 用户需要的是最终的 JSON 结果（已保存为 `*-discovery.json`），不是过程日志
- 流面板仅用于实时查看，发现完成后自动收起

**保留的日志**：
- 每个 discovery 操作完成后，仍然保存 `api-discovery.json` / `frontend-discovery.json` / `review-discovery.json` + `review-rules.json`
- 如果解析失败（0 模块），在 done 事件中携带 `rawOutput` 的前 2000 字符，前端显示「解析失败，原始输出预览」

### 错误处理增强

当前 parseReviewOutput 用正则匹配 ` ```json``` `，非常脆弱。改进：

1. **多重解析策略**：先尝试提取 json block → 失败则尝试全文 JSON.parse → 失败则返回原始输出
2. **done 事件携带解析状态**：如果解析到 0 模块，标记 `parseWarning: true`
3. **前端展示**：如果收到 `parseWarning`，在进度面板底部显示黄色警告：「解析未获得有效结果，可能是 Skill 输出格式不匹配，建议检查 SKILL.md」

### 实施步骤

1. 修改 4 个发现服务（api / frontend / review / page-context）的 onProgress 回调，推送原始 Claude Code 消息块
2. SettingsView 添加 discoveryStreams 状态和 handleDiscoverySSE 处理函数
3. SettingsView 添加实时流面板模板（text + ToolCallBlock）
4. 增强 parseReviewOutput / parseDiscoveryOutput 的容错解析
5. 在前端 api 调用处接入新的 SSE 处理逻辑
6. 测试：点击发现按钮，确认实时看到 Claude Code 的工具调用和文本输出

### 不涉及的改动

- 不改 E2E 页面发现的流式逻辑（已经好用）
- 不改 test-events.ts 的事件总线（发现服务不需要跨页面订阅）
- 不保存过程日志到文件（只保留最终 JSON 结果）
- 不需要数据库存储
