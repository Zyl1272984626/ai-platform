# 发现服务中断功能设计方案

## 背景

设置页面的各类"发现"功能（发现页面、发现组件、发现接口、发现审查点、生成图谱）在执行时，用户点击进度面板上的【关闭】按钮，仅会隐藏 UI 面板，**不会中断后端的 Claude Code 请求**。后端进程会继续运行直到自然完成，浪费资源。

需要新增中断能力，让用户可以主动终止正在执行的发现任务。

---

## 现状分析

### 当前"关闭"按钮行为

- 执行 `delete discoveryStreams[key]`，仅从 reactive 对象中删除 key
- SSE 连接保持，后端 Claude Code 进程继续运行
- 无任何中断通知发送到后端

### 已有的中断参照实现

项目中 `test-runner.ts` 已实现完整的 abort 链路：

- 全局 Map 存储 AbortController（`test-runner.ts:58`）
- 导出 `abortTestRun(id)` 函数（`test-runner.ts:1320-1326`）
- API 路由 `POST /tests/runs/:id/abort`（`routes/test.ts:151-154`）
- 前端 `abortTestRun(id)` API 函数（`web/src/api/tests.ts:48-49`）

### 当前后端 AbortController 状态

每个发现服务（api-discovery、frontend-discovery、review-discovery、page-context-discovery）都已创建 `AbortController`，并在 `for-await` 循环中检查 `signal.aborted`。但它是函数局部变量，无法从外部触发 abort。

---

## 设计方案

### 整体链路

```
用户点击【中断】
  → 前端调用 POST /api/projects/:id/discover-abort  (body: { type })
    → 路由层从全局 Map 取出 AbortController
      → 调用 controller.abort()
        → 后端 for-await 循环检测到 signal.aborted，抛异常退出
          → Claude Code query 被中断
          → SSE 连接关闭
        → 前端同时 abort fetch 连接
  → 隐藏进度面板，显示"已中断"
```

### 涉及文件清单

| 层 | 文件 | 改动内容 |
|---|---|---|
| 后端服务层 | `server/src/services/api-discovery.ts` | AbortController 提升到模块级 Map |
| 后端服务层 | `server/src/services/frontend-discovery.ts` | 同上 |
| 后端服务层 | `server/src/services/review-discovery.ts` | 同上 |
| 后端服务层 | `server/src/services/page-context-discovery.ts` | 同上 |
| 后端路由层 | `server/src/routes/projects.ts` | 新增 abort 路由 |
| 前端 API 层 | `web/src/api/projects.ts` | 新增 abortDiscovery 函数 |
| 前端 UI 层 | `web/src/views/SettingsView.vue` | 按钮改为中断功能 |

## 详细设计

### 1. 后端服务层改造

每个发现服务文件做相同模式的改造（以 api-discovery.ts 为例）：

```typescript
// 模块级 Map，存储正在执行的发现任务的 AbortController
const abortControllers = new Map<string, AbortController>();

/**
 * 中断指定项目的发现任务
 * @param projectId 项目 ID
 * @returns 是否成功中断
 */
export function abortDiscovery(projectId: string): boolean {
  const controller = abortControllers.get(projectId);
  if (controller) {
    controller.abort();
    abortControllers.delete(projectId);
    return true;
  }
  return false;
}

// 在 discoverApi 函数内部：
export async function discoverApi(projectId: string, onProgress: (data: any) => void) {
  // ...
  const abortController = new AbortController();
  abortControllers.set(projectId, abortController);  // 存入 Map

  try {
    // ... 现有的 query + for-await 逻辑
  } finally {
    abortControllers.delete(projectId);  // 确保清理
  }
}
```

需要改造的 4 个服务文件及其 Map key 约定：

| 服务文件 | Map key | 说明 |
|----------|---------|------|
| api-discovery.ts | `projectId` | API 接口发现 |
| frontend-discovery.ts | `projectId` | 前端组件发现 |
| review-discovery.ts | `projectId` | 代码审查发现 |
| page-context-discovery.ts | `projectId` | 知识图谱发现 |

### 2. 后端路由层

在 `server/src/routes/projects.ts` 新增统一中断路由：

```typescript
// POST /:id/discover-abort
router.post('/:id/discover-abort', async (req, res) => {
  const { id } = req.params;
  const { type } = req.body;  // type: 'api' | 'frontend' | 'review' | 'context' | 'e2e'

  let aborted = false;
  switch (type) {
    case 'api':
      aborted = abortDiscoveryApi(id);
      break;
    case 'frontend':
      aborted = abortDiscoveryFrontend(id);
      break;
    case 'review':
      aborted = abortDiscoveryReview(id);
      break;
    case 'context':
      aborted = abortDiscoveryContext(id);
      break;
    case 'e2e':
      aborted = abortDiscoveryE2E(id);
      break;
  }

  res.json({ success: aborted, message: aborted ? '已中断' : '未找到正在执行的任务' });
});
```

### 3. 前端 API 层

在 `web/src/api/projects.ts` 新增：

```typescript
/** 中断发现任务 */
export function abortDiscovery(projectId: string, type: string) {
  return fetch(`/api/projects/${projectId}/discover-abort`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ type }),
  }).then(res => res.json());
}
```

### 4. 前端 UI 层改造

#### 4.1 保存前端 SSE 的 AbortController

`doDiscoverApi` 等函数内部创建 fetch 时，保存 AbortController 引用到 discoveryStreams 中：

```typescript
interface StreamState {
  // ... 现有字段
  fetchAbort?: AbortController;  // 新增：用于中断 fetch 连接
}
```

#### 4.2 按钮行为改造

将进度面板中的【关闭】按钮改为【中断】按钮：

```html
<!-- 改造前 -->
<button class="btn btn-xs" @click="delete discoveryStreams[`${project.id}-${dtype}`]">
  关闭
</button>

<!-- 改造后 -->
<button class="btn btn-xs btn-error"
  :disabled="discoveryStreams[key]?.aborting"
  @click="abortDiscoveryTask(project.id, dtype)">
  {{ discoveryStreams[key]?.aborting ? '中断中...' : '中断' }}
</button>
```

#### 4.3 中断处理函数

```typescript
async function abortDiscoveryTask(projectId: string, type: string) {
  const key = `${projectId}-${type}`;
  const stream = discoveryStreams[key];
  if (!stream) return;

  // 标记中断中状态
  stream.aborting = true;

  try {
    // 1. 通知后端中断
    await abortDiscovery(projectId, type);

    // 2. 中断前端 SSE 连接
    stream.fetchAbort?.abort();
  } finally {
    // 3. 隐藏进度面板
    delete discoveryStreams[key];
  }
}
```

## 交互设计

### 按钮状态流转

```
[发现中...]  →  进度面板显示，出现【中断】按钮（红色）
      ↓ 用户点击【中断】
[中断中...]  →  按钮变为 disabled，显示"中断中..."
      ↓ 后端确认中断
面板关闭     →  进度面板消失，可重新发起发现
```

### 发现按钮状态

发现按钮的 disabled 逻辑不变（`discoveringApiProject === project.id` 时禁用），中断后需要重置该状态：

```typescript
// 中断成功后重置发现状态
discoveringApiProject.value = null;  // 对应类型的状态变量
```

---

## 注意事项

1. **资源清理**：后端 `finally` 块中必须删除 Map 中的 AbortController，防止内存泄漏
2. **并发安全**：同一项目同一类型同时只能有一个发现任务，无需担心多个 AbortController 冲突
3. **E2E 发现**：`page-discovery.ts` 使用 Playwright 而非 Claude Code，中断时需要额外处理浏览器进程关闭
4. **部分结果**：中断后如果已有部分写入文件的结果，需要决定是保留还是清理（建议保留，作为下次发现的参考）
