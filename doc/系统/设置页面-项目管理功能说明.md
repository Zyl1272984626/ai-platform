# 设置页面 — 项目管理功能说明

## 概览

设置页面（`/settings`）的**项目管理**区块是 E2E 多项目测试的核心入口。每个被测系统作为一个"项目"添加，支持独立配置地址、凭据，并可自动发现页面路由。

## 页面布局

```
┌─────────────────────────────────────────────────────────┐
│ 项目管理                                     [+ 添加项目] │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 主系统(Agent)                    ● 默认  ✅ 活跃    │  │
│  │ http://localhost:5173                               │  │
│  │ 页面集: 27 个 | 页面: 75 个 | 发现于: 06/01 12:01  │  │
│  │                                                    │  │
│  │   [设为默认] [编辑] [发现页面] [检测] [删除]         │  │
│  └────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

## 按钮功能说明

### 「+ 添加项目」

**作用**：添加一个新的被测项目。弹窗要求填写：

| 字段 | 必填 | 说明 |
|------|------|------|
| 项目名称 | 是 | 显示名，如"主系统(Agent)" |
| 前端地址 | 是 | 被测系统前端 URL，如 `http://localhost:5173` |
| 后端 API 地址 | 否 | 默认同前端地址 |
| 登录页路径 | 否 | 默认 `/web/index.html#/login` |
| 用户名 / 密码 | 是 | 用于自动登录和页面发现 |
| 源码路径 | 否 | 提供后可增强发现（源码分析模式） |

**实现**：前端调 `POST /api/projects`，后端在 `config.ts` 中创建 `TestProject` 对象，持久化到 `server/data/platform-config.json`。

---

### 「发现页面」

**作用**：一键自动探测该项目的所有页面路由，生成可测试的页面集。

**用户看到的效果**：
1. 按钮变为"发现中..."
2. 下方出现进度面板，实时显示：
   - "正在启动浏览器..."
   - "正在登录..." → "登录成功"
   - "探测 12 个可能的入口..." → "✅ web — 有效 Vue 应用"
   - "正在提取 admin 的路由..." → "admin: 27 条路由"
   - "正在分组整理..."
   - "发现完成: 27 个页面集, 75 个可测试页面"
3. 项目卡片上的"页面集/页面"数字自动刷新

**背后的完整流程**：

```
前端点击"发现页面"
  → POST /api/projects/:id/discover (SSE 流式响应)
  → 后端 page-discovery.ts 启动 Playwright Chromium
  → 1. 导航到登录页，填写凭据登录
  → 2. 从登录后 URL 推断部署根路径（如 / 或 /agent_audio/）
  → 3. 对已知入口名逐一探测：
       GET http://目标/{入口}/index.html
       → 等待 1 秒，检查 #app 下是否有 Vue 实例
       → 有 __vue_app__ = 有效入口，无 = 跳过
  → 4. 对每个有效入口：
       page.evaluate(() => app.__vue_app__.$router.getRoutes())
       提取 path/name/title/meta 信息
       自动解析动态参数（如 :businessSystemId → assistant）
  → 5. 按路由路径前缀自动分组生成 PageSet[]
  → 6. 保存到 platform-config.json 的项目 pageSets
  → 7. 生成 page-context.json 知识库骨架
  → SSE 逐阶段推送进度到前端
```

**关键代码文件**：

| 文件 | 职责 |
|------|------|
| `server/src/services/page-discovery.ts` | 发现核心逻辑（Playwright + Vue Router 提取） |
| `server/src/routes/projects.ts` | SSE 流式 API 路由 |
| `web/src/api/projects.ts` | 前端 SSE fetch 流式接收 |
| `web/src/views/SettingsView.vue` | 发现按钮 + 进度面板 UI |

**产出物**：
- `platform-config.json` 中项目的 `pageSets` 数组被填充
- `server/data/projects/{projectId}/page-context.json` 生成知识库骨架

---

### 「检测」

**作用**：检测该项目的连通性，验证配置是否正确。

**检测项**：

| 检测项 | 方法 | 说明 |
|--------|------|------|
| 前端地址 | HTTP GET baseUrl | 目标前端是否可访问 |
| 后端 API | HTTP GET apiBaseUrl/api/health | 目标后端是否可访问 |
| 登录页 | HTTP GET baseUrl + loginUrl | 登录页是否能打开 |
| 源码路径 | fs.existsSync | 本地源码目录是否存在（仅配置了时检测） |

**结果展示**：项目卡片下方显示每个检测项的 ✅/❌ 标签。

**实现**：`POST /api/projects/:id/check`，在 `routes/projects.ts` 中直接 fetch 探测。

---

### 「编辑」

**作用**：修改项目配置（名称、地址、凭据等）。密码不回显，留空则不修改。

### 「设为默认」

**作用**：将该项目设为默认项目。测试页面（`/tests`）的 E2E 测试默认选中此项目。

### 「删除」

**作用**：删除项目及其所有页面集数据。需确认弹窗。

---

## 与测试页面的联动

设置页面完成项目添加和页面发现后，在**测试页面**（`/tests`）：

1. 切到 **E2E** tab
2. 「目标项目」下拉框自动列出所有活跃项目
3. 选择项目后，「测试范围」下拉框自动加载该项目的页面集：
   - "全部页面" — 该项目所有已发现页面
   - "sys (admin, 6页)" — 只测系统管理页面集
   - "chat (web, 3页)" — 只测对话页面集
   - ...每个页面集对应发现时自动生成的分组
4. 点击"开始测试" → 后端从项目配置读取页面列表和凭据，动态构建测试 prompt

---

## 数据流

```
设置页面添加项目 → platform-config.json (projects[])
         ↓
点击"发现页面" → Playwright 启动浏览器 → Vue Router getRoutes()
         ↓
生成 pageSets[] → 写入 platform-config.json
         ↓
生成 page-context.json 骨架 → server/data/projects/{id}/
         ↓
测试页面选择项目 → 加载 pageSets → 选择范围 → 开始测试
         ↓
test-runner.ts 读取项目配置 → 动态构建 prompt → Claude Code + Playwright MCP 执行
```

## 技术细节

### Vue Router 提取原理

Vue SPA 应用在浏览器运行后，Vue 实例挂载在 `#app` 元素上。通过 Playwright 的 `page.evaluate()` 可以直接访问：

```javascript
const app = document.querySelector('#app');
const router = app.__vue_app__.config.globalProperties.$router;
const allRoutes = router.getRoutes(); // 返回所有注册路由的完整信息
```

这是唯一可靠的 100% 覆盖率方案（DOM 链接提取对 Vue SPA 无效，点击遍历太慢且不完整）。

### 部署根路径推断

登录后 URL 格式有两种情况：
- 本地开发：`http://localhost:5173/index/index.html#/...` → 根路径 `/`
- 线上部署：`https://xxx.com/agent_audio/web/index.html#/...` → 根路径 `/agent_audio/`

解析规则：取路径段，去掉最后一段（子应用名）和 `index.html`，剩下的就是根路径。只有一段时根路径为 `/`。

### 入口误判防护

本地 Vite 开发服务器对所有路径返回同一个 `index.html`（SPA 模式），会导致误判。解决：探测时不仅检查 HTML 内容，还等待 1 秒后检查 `__vue_app__` 是否实际存在。不存在的说明该路径没有独立的 Vue 应用。
