# 代码审查测试设计方案（v2）

## 1. 核心理念：发现 → 生成 → 执行

代码审查同样遵循三阶段模式，但与 API 测试和前端测试不同的是，**执行阶段也由 Claude Code 驱动**（需要 AI 理解代码语义才能审查）。

### 1.3 文件存储结构

采用**轻量配置 + 外部重数据**分离存储：

```
┌─ server/data/                    ← 轻量配置（随项目 Git 管理，KB 级）
│  └── projects/{id}/
│     ├── project.json               E2E 页面集数据（已有）
│     ├── discovery-result.json      E2E 发现结果（已有）
│     ├── page-context.json          E2E 页面知识库（已有）
│     ├── review-discovery.json      审查发现结果（新增）
│     └── review-rules.json          AI 生成的审查规则（新增）
│
└─ {testDataDir}/                  ← 统一外部数据目录（设置页面配置一项即可）
   ├── e2e/                          E2E 运行数据（原 e2eDataDir 迁入）
   ├── api/runs/
   ├── frontend/runs/
   └── codereview/
       └── runs/{suiteId}.json         代码审查运行记录（含 issues、score）
```

> **设计原因**：所有测试类型的运行产物统一放一个外部目录，
> `server/data/` 只保留轻量 JSON 配置。
> 设置页面只需配一个 `testDataDir`（如 `F:/test-runs-data`）。

## 2. 与 E2E / API / 前端测试的对比

| 维度 | E2E 页面测试 | API 接口测试 | 前端单元测试 | 代码审查 |
|------|------------|------------|------------|---------|
| **发现** | Playwright + 浏览器 | Claude Code | Claude Code | Claude Code |
| **生成** | page-context.json | api-tests.json | .test.ts 文件 | review-rules.json |
| **执行** | Claude Code + Playwright | 后端 fetch | vitest run | Claude Code |
| **执行需 AI** | 是 | 否 | 否 | 是 |
| **配置存储** | `server/data/projects/{id}/` | 同左 | 同左 | 同左 |
| **运行数据** | `{testDataDir}/e2e/` | `{testDataDir}/api/` | `{testDataDir}/frontend/` | `{testDataDir}/codereview/` |
| **外部目录** | 统一 `testDataDir`（如 `F:/test-runs-data`），原 `e2eDataDir` 废弃 | 同左 | 同左 | 同左 |

代码审查的特殊性：**发现、生成、执行三个阶段都需要 Claude Code**。

## 5. 执行阶段：Claude Code 流式审查

### 5.1 与 E2E 类似的执行方式

代码审查的执行阶段类似 E2E 测试——**调用 Claude Code SDK，注入审查规则作为 Skill/Prompt，流式返回审查结果**。

### 5.2 执行流程

```typescript
async function runCodeReview(suite: TestSuite, config: Record<string, unknown>): Promise<void> {
  const projectId = config.projectId as string
  const project = getProjectById(projectId)
  const sourcePath = project?.sourcePath

  // 1. 读取项目级审查规则
  const rulesPath = path.join(DATA_DIR, 'projects', projectId, 'review-rules.json')
  const rules = JSON.parse(fs.readFileSync(rulesPath, 'utf-8'))

  // 2. 收集目标文件
  const scope = config.scope as string || 'diff'  // full / diff / files
  const files = collectReviewFiles(sourcePath, scope, rules.ignore.patterns)

  // 3. 筛选启用的维度
  const enabledDimensions = rules.dimensions.filter(d =>
    (config.dimensions as string[] || []).includes(d.id)
  )

  // 4. 按 batch 分组
  const batches = batchFiles(files, rules.fileLimits.maxFilesPerReview)

  for (const tc of suite.cases) {
    const batch = batches.find(b => b.label === tc.name)
    if (!batch) { tc.status = 'skipped'; continue }

    tc.status = 'running'
    tc.blocks = []  // 存储流式事件
    saveRun(suite)
    testBus.emit('test:update', { suiteId: suite.id, caseId: tc.id, caseName: tc.name, status: 'running' })

    const startTime = Date.now()

    try {
      // 5. 构建审查 Prompt
      const systemPrompt = buildReviewSystemPrompt(enabledDimensions)
      const userPrompt = buildReviewUserPrompt(project.name, scope, batch.files)

      // 6. 调用 Claude Code SDK（与 E2E 类似）
      const { query } = await import('@anthropic-ai/claude-code')
      const messages: any[] = []

      await query({
        prompt: userPrompt,
        options: {
          systemPrompt,
          maxTurns: 20,
          allowedTools: ['Read', 'Grep', 'Glob'],
          cwd: sourcePath,
        },
        onMessage: (msg) => {
          // 流式推送审查进度
          if (msg.type === 'assistant') {
            const block: StreamBlock = { type: 'text', content: msg.content }
            tc.blocks!.push(block)
            testBus.emit('agent:stream', { suiteId: suite.id, type: 'text', content: msg.content })
          }
          messages.push(msg)
        },
        abortController: getAbortController(suite.id),
      })

      // 7. 解析审查结果
      const reviewResult = parseReviewFromMessages(messages)
      tc.duration = Date.now() - startTime
      tc.status = 'passed'  // 审查完成即为 passed
      tc.output = JSON.stringify(reviewResult, null, 2)
      tc.metadata = { review: reviewResult }

    } catch (err: any) {
      tc.duration = Date.now() - startTime
      tc.status = 'error'
      tc.error = err.message
    }

    saveRun(suite)
    testBus.emit('test:update', { suiteId: suite.id, caseId: tc.id, caseName: tc.name, status: tc.status })
  }
}
```

## 6. 文件收集策略

### 6.1 三种范围

```typescript
function collectReviewFiles(
  sourcePath: string,
  scope: 'full' | 'diff' | 'files',
  ignorePatterns: string[],
  specifiedFiles?: string[]
): ReviewFile[] {
  switch (scope) {
    case 'full':
      // 全量：扫描所有 .vue/.ts/.js 文件
      return scanSourceFiles(sourcePath, ignorePatterns)

    case 'diff':
      // 增量：最近 N 次提交的变更文件
      const diff = execSync('git diff --name-only HEAD~10', { cwd: sourcePath, encoding: 'utf-8' })
      return diff.trim().split('\n')
        .filter(f => /\.(vue|ts|js|tsx|jsx)$/.test(f))
        .filter(f => !isIgnored(f, ignorePatterns))
        .map(f => ({ path: f, content: readFileSync(path.join(sourcePath, f), 'utf-8') }))

    case 'files':
      // 指定文件
      return (specifiedFiles || []).map(f => ({
        path: f,
        content: readFileSync(path.join(sourcePath, f), 'utf-8')
      }))
  }
}
```

## 9. 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 规则生成 | Claude Code 基于源码分析生成 | 比人工写规则更贴合项目实际 |
| 规则存储 | `projects/{id}/review-rules.json` | 分项目存储，可独立更新 |
| 执行方式 | Claude Code SDK（同 E2E） | 审查需要 AI 理解代码语义 |
| 审查范围 | 默认增量（diff） | 全量审查太慢，增量更实用 |
| 评分机制 | AI 输出 0-100 分 | 直观展示代码质量趋势 |
| 发现与执行分离 | 是 | 规则可复用，不需要每次审查都重新发现 |
