### 安全性

#### 🔴 SEC001-01 | v-html 未做净化处理 — XSS 风险
**文件**: `views/app/skill/detail.vue:68`
```html
<pre v-if="isMarkdown" v-html="renderedContent"></pre>
```
**问题**: `simpleMarkdownRender` 函数（行192-202）虽然先做了 `&`/`<`/`>` 转义，再替换 Markdown 标记为 HTML 标签，但存在绕过风险。例如输入 `**foo**<script>alert(1)</script>` 时，先被转义为 `&lt;script&gt;`，再被 `<strong>` 包裹，看似安全。但如果后续引入 `marked` 库（代码注释中明确提到"后续替换为 marked 库"），替换后未使用 DOMPurify 凓化则存在 XSS 风险。
**修复建议**: 即使当前简单渲染看起来安全，也应引入 DOMPurify 对最终 HTML 做净化。替换为 `marked` 库时必须配合 DOMPurify。

#### 🔴 SEC001-02 | innerHTML 注入未净化内容
**文件**: `views/app/comp/CompPreviewPage.vue:234`
```js
container.innerHTML = `<div style="color:#f56c6c;padding:20px;">渲染失败: ${e.message}</div>`
```
**问题**: `e.message` 来自动态组件加载异常，可能包含用户输入的恶意内容，直接拼接到 innerHTML 中存在 XSS 风险。
**修复建议**: 使用 `document.createElement` 构建错误提示 DOM，或对 `e.message` 进行 HTML 转义。

#### 🔴 SEC001-03 | dangerouslyUseHTMLString 用于工作流导入提示
**文件**: `views/app/workflow/import-dialog.vue:341`
**问题**: 使用 `dangerouslyUseHTMLString: true` 展示 `${reason}` 变量拼接的 HTML，reason 来自导入文件解析逻辑，如果文件内容被精心构造，可能导致 XSS。
**修复建议**: 避免使用 `dangerouslyUseHTMLString`，改用纯文本展示或对 reason 进行转义。

#### 🟡 SEC001-04 | dangerouslyUseHTMLString 用于 API 配置测试结果

**修复建议**: 确认 `escapeHtml` 实现完备，或改用纯文本 `<pre>` 标签展示。

#### 🔴 SEC001-05 | flowList.js 构造含 onclick 的 HTML 字符串

onclick="window.location.href=('${agent.agentType}' === 'CONVERSATION'

**修复建议**: 对所有动态值进行 HTML 属性转义，或改用 Vue 组件渲染引用列表。

### 性能

#### 🔴 PERF001-01 | eChart.js resize 监听器未清理 — 内存泄漏
**文件**: `views/app/analytics/eChart.js:101`
```js
window.addEventListener('resize', () => chart.resize())
```
**问题**: 每次调用 `initChart` 都会向 window 注册一个新的 resize 监听器，且从不移除。多次调用会导致监听器堆积，echarts 实例也未被 dispose。
**修复建议**: 保存监听器引用，在组件卸载时 `removeEventListener` 并 `chart.dispose()`。

#### 🟡 PERF001-02 | UploadDialog 和 ManualExtractDialog 轮询无 AbortController

**修复建议**: 引入 `AbortController` 或在 `watch(visible)` 中设置取消标志，弹窗关闭时中止轮询。

#### 🟡 PERF001-03 | ConversationAnalysis setInterval 未在组件卸载时保证清理

#### 🟡 PERF003-01 | useCharts.js echarts 实例未在组件卸载时 dispose

### 错误处理

#### 🟡 ERR001-01 | agentList.js 模块级 ref 导致多实例数据共享
**文件**: `common/agentList.js:8-9`
```js
let agentList = ref([])
let isInit = false
```
**问题**: `agentList` 和 `isInit` 定义在模块顶层，所有使用 `useAgentList()` 的组件共享同一份数据和初始化状态。`isInit` 一旦设为 true 就不会重置，导致后续新挂载的组件无法触发初始加载。
**修复建议**: 将 `agentList` 和 `isInit` 移入 `useAgentList` 函数内部，或改用 Pinia store 管理状态。

#### 🟡 ERR001-02 | flowList.js 同样的模块级状态问题

**修复建议**: 同上，移入函数内部或使用 Pinia。

#### 🟡 ERR002-01 | UploadDialog 串行上传 — 一个失败不阻塞后续

#### 🔵 ERR003-01 | activateAgent.js refreshAgentInfo 缺少错误恢复

#### 🔵 ERR004-01 | flow-design.vue loadSchema 异常被吞

### 框架最佳实践

## 总结

### 关键风险

1. **XSS 安全风险（高）**: `flowList.js` 的 `deleteFlow` 函数将未转义的用户数据直接拼接到 HTML `onclick` 属性中，通过 `alertHtml` 渲染，是最严重的 XSS 入口。`skill/detail.vue` 的 `v-html` 和 `CompPreviewPage.vue` 的 `innerHTML` 也需关注。

2. **内存泄漏（中高）**: `eChart.js` 每次初始化图表都注册 resize 监听器且从不移除，echarts 实例也未 dispose，在频繁切换页面的场景下会持续泄漏。

3. **轮询未取消（中）**: `UploadDialog` 和 `ManualExtractDialog` 的 `pollStatus` 轮询（最长 6 分钟）在弹窗关闭后仍继续执行，浪费网络和计算资源。

### 架构问题

- **模块级 ref 状态共享**: `agentList.js`、`flowList.js`、`activateAgent.js` 三个核心 composable 都使用模块顶层变量，导致状态在所有组件间全局共享。这在单页应用切换路由时可能导致数据残留或状态不一致。建议迁移到 Pinia store。

### 亮点

- 表单验证规范（edit.vue 有完整的验证规则和长度限制）
- echarts 实例重复初始化处理得当（useCharts.js 先 dispose 再 init）
- 文件上传的进度展示和状态管理设计良好
- API 请求有并发锁机制（activateAgent.js 的 refreshingPromise）
- 事件监听器清理普遍做得较好（agent/index.vue、analytics-detail/index.vue 等）
