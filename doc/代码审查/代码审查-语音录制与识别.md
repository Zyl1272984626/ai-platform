## 问题列表

### 1. 🟡 AudioUtils.convertToWav 缺少 try-catch，AudioContext 泄漏
- **规则 ID**: ERR001
- **文件**: `AudioUtils.js:9-31`
- **问题描述**: `convertToWav` 方法中创建了 `AudioContext`（行11），若后续的 `audioBlob.arrayBuffer()`（行10）或 `audioContext.decodeAudioData()`（行12）抛出异常，`audioContext.close()`（行13）将不会被执行，导致 AudioContext 资源泄漏。浏览器对同时存在的 AudioContext 数量有限制（通常6个），多次失败可能导致后续录音无法初始化。
- **修复建议**: 使用 try-finally 确保 AudioContext 关闭：
  ```js
  static async convertToWav(audioBlob) {
    const arrayBuffer = await audioBlob.arrayBuffer()
    const audioContext = new (window.AudioContext || window.webkitAudioContext)()
    try {
      const originalBuffer = await audioContext.decodeAudioData(arrayBuffer)
      // ... 后续处理
    } finally {
      audioContext.close()
    }
  }
  ```

### 2. 🟡 AudioUtils.checkMinDuration 同样存在 AudioContext 泄漏
- **规则 ID**: ERR001
- **文件**: `AudioUtils.js:83-98`
- **问题描述**: `checkMinDuration` 中通过 FileReader 加载音频后创建 AudioContext（行88），若 `decodeAudioData` 抛出异常，虽然 catch 会 resolve(false)，但 audioContext.close() 不会被执行。
- **修复建议**: 在 try 块中添加 finally 确保 close，或统一抽取 AudioContext 管理工具方法。

### 3. 🟡 全部文件为 JS，无 TypeScript 类型安全
- **规则 ID**: FW004
- **文件**: `VoiceRecorder.js`, `AudioUtils.js`, `useVoiceRecorder.js`
- **问题描述**: 三个文件全部使用 `.js`，无类型注解。`VoiceRecorder` 的 options 对象、`AudioUtils` 的静态方法参数和返回值均无类型约束，容易在调用时传错参数（如 `convertToWav` 传入非 Blob 对象）。
- **修复建议**: 将文件迁移为 `.ts`，至少为 `VoiceRecorder` 的 options 接口和 `AudioUtils` 的公共方法添加类型定义。

### 4. 🟡 Magic Number 未提取为命名常量
- **规则 ID**: MNT004
- **文件**: 多处
- **问题描述**:
  - `VoiceRecorder.js:62` — `500`（最短录音时长 ms）
  - `useVoiceRecorder.js:53` — `60`（最大录音时长 s）
  - `AudioUtils.js:15` — `16000`（目标采样率 Hz）
  - `AudioUtils.js:44` — `44`（WAV header 大小）
  - 这些数字直接出现在逻辑中，缺乏语义化命名。
- **修复建议**: 在文件顶部或单独的 constants 中定义：
  ```js
  const MIN_RECORDING_DURATION_MS = 500
  const MAX_RECORDING_DURATION_S = 60
  const TARGET_SAMPLE_RATE = 16000
  const WAV_HEADER_SIZE = 44
  ```

### 5. 🔵 console.error 调试日志残留
- **规则 ID**: MNT003
- **文件**: `VoiceRecorder.js:39`, `VoiceRecorder.js:104`
- **问题描述**: 两处 `console.error` 直接输出原始 error 对象到控制台，生产环境下不应暴露内部错误细节。不过这两处都在 catch 块中，同时通过 `onError` 回调向用户展示了友好消息，所以功能上没有问题。
- **修复建议**: 生产构建时通过构建配置移除 console.error，或使用统一的 logger 工具。

### 6. 🔵 文件上传无大小限制
- **规则 ID**: SEC006
- **文件**: `VoiceRecorder.js:94`
- **问题描述**: `processAudio` 中通过 `api.upload` 上传音频文件，没有对文件大小做前端校验。虽然录音时长有 60s 的 UI 层限制（useVoiceRecorder.js:53），但 `VoiceRecorder` 类本身没有录制时长或文件大小的硬限制。如果 `VoiceRecorder` 被其他场景复用，可能上传超大文件。
- **修复建议**: 在 `processAudio` 中添加文件大小校验（如最大 5MB），或在 `startRecording` 时传入最大时长参数。

## 总结

语音录制模块整体架构设计**优秀**，两阶段初始化方案（prepare + sync start）巧妙解决了移动端触摸事件与异步权限请求的冲突，这是该模块最大的亮点。资源清理方面，`destroy()` 方法完整地处理了 MediaRecorder、Stream tracks 和 Timer 的释放，composable 层也在 `destroyVoiceRecorder` 中做了完善的清理。

**主要改进方向**：
1. **AudioUtils 异常安全**（优先级最高）— `convertToWav` 和 `checkMinDuration` 中的 AudioContext 需要 try-finally 保护，否则异常时会泄漏音频上下文资源
2. **TypeScript 迁移** — 三个文件的公共 API 应添加类型定义，特别是 `VoiceRecorder` 的 options 接口
3. **常量提取** — 将魔法数字提取为命名常量，提高代码可读性

**设计亮点**：
- 两阶段录音方案解决移动端兼容性问题
- stream tracks 在 destroy 中正确释放
- durationTimer 在所有退出路径上清理
- 最短录音时长（500ms）和最长录音时长（60s）的双重保护
- 回调模式 + composable 的分层设计，VoiceRecorder 可独立于 Vue 使用
